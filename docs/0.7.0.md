# Release 0.7.0

Minor release 0.7.0. This is a coordinated workspace-wide minor bump: every published `@solidiom/*` package moves from `0.6.0` to `0.7.0` in lockstep. The release advances the Solid 2 support window from `2.0.0-rc.11` to the `2.0.0-rc.21` tier (peer floor `>=2.0.0-rc.18 <3.0.0`), migrates all 30 Solid Router templates to the Router 2.x config API, repairs the compat-matrix tooling so nightly tier testing is real, and hardens the browser/e2e lanes. The catalog itself is unchanged in size: 87 primitives (53 `stable`, 34 `experimental`), 32 components, 36 blocks, 6 adapters, 31 templates, 4 theme presets.

## Versioning

All 103 published packages are versioned together at `0.7.0`. Internal-only packages (`@solidiom/bench`, `@solidiom/eslint-plugin-solidiom`, `@solidiom/adapter-kit`, `@solidiom/release-tools`, `@solidiom/test-doubles`, and the probe harnesses) are excluded from release and remain unpublished. The 31 template packages (`@solidiom/template-*`) are private starters and keep their independent `0.0.1-next.0` versioning.

## Highlights

- **Solid 2 support window advanced to the `2.0.0-rc.21` tier.** The rolling matrix moved `rc.11 → rc.20 → rc.21`; the installed toolchain pins `solid-js` and `@solidjs/web` at `2.0.0-rc.21` (`@solidjs/signals` follows transitively). The peer range is now the explicit prerelease-aware `>=2.0.0-rc.18 <3.0.0` instead of a caret range.
- **All 30 Solid Router templates migrated to `@solidjs/router@2.0.0-next.43`.** The Router 2.x config-API rewrite replaces the JSX route tree with `createRouter({ routes: defineRoutes([...]) })`, drops `<A>` in favor of plain anchors, and fixes a stale `jsxImportSource` in 29 template tsconfigs. This is the one intentionally breaking surface in this release (templates only; no published package API changes).
- **The compat matrix became real.** `scripts/set-solid-version.mjs` was silently forcing `babel-preset-solid` to nonexistent tier versions — pnpm ignores overrides that match nothing, so every nightly tier was actually testing the pinned toolchain. The compiler pin now comes from a dedicated matrix `compiler` field, and every resolved version is verified against the npm registry before being written.
- **Solid 2 GA transition tooling rewritten.** `scripts/solid2-stable-transition.mts` (the on-GA-day switch) no longer clobbers the matrix schema, verifies every version against npm before writing anything, refuses prerelease input, and regenerates the lockfile.
- **Every package test lane now runs the shared config.** All ~100 package `test` scripts point at the shared root/node vitest config, so the browser-test exclusion actually applies; previously the exclusion only worked when the suite happened to run from the repo root.

## Solid 2 compatibility

| Item                  | 0.6.0                                    | 0.7.0                                                       |
| --------------------- | ---------------------------------------- | ----------------------------------------------------------- |
| Window (low/mid/high) | `rc.6 / rc.8 / rc.11`                    | `rc.18 / rc.20 / rc.21`                                     |
| Installed toolchain   | `solid-js`, `@solidjs/web` `2.0.0-rc.11` | `solid-js`, `@solidjs/web` `2.0.0-rc.21`                    |
| Compiler pin          | forced to the tier version               | `babel-preset-solid` `2.0.0-rc.2` (matrix `compiler` field) |
| Peer range            | `^2.0.0-rc.6` (`>=rc.11` catalog floor)  | `>=2.0.0-rc.18 <3.0.0`                                      |

- `babel-preset-solid` stays at `2.0.0-rc.2`: its release line is version-decoupled from the runtime and npm's `next` tag is still that exact version.
- The peer floor tracks the window low tier. `rc.16` remains the lowest tier ever verified green (build + node + browser), so nothing previously supported is dropped below the tested floor; the rc.8 low tier was tested and fails on rc.9+ runtime internals, which is why the floor moved.
- Companion pins: `@solidjs/testing-library` moves `^1.0.0-beta.3` → `^1.0.0-rc.2` (registry `next` tag; peers `>=2.0.0-0`), node and browser suites green on rc.2. `vite-plugin-solid` stays at `3.0.0-next.27` — npm's `next` tag is that exact version.

## Notable changes

### Tooling and compat matrix

- **`tools/solid-matrix.json`** gains a `compiler` field separating the runtime window from the compiler pin.
- **`scripts/set-solid-version.mjs`** takes the compiler pin from the matrix instead of forcing `babel-preset-solid` to the tier version, and verifies every resolved version against the npm registry before writing — a nonexistent override target now fails the build loudly instead of being silently ignored.
- **`scripts/update-solid-window.mts`** keeps the compiler pin, verifies the new version exists on npm, generates a prerelease-aware peer range, and rewrites only inside the `catalog:`/`overrides:` YAML blocks with a key regex that handles both bare and quoted keys (the old positional regex silently skipped unquoted keys).
- **`scripts/solid2-stable-transition.mts`** rewritten: keeps the matrix schema (window collapsed to the stable version, compiler resolved from npm), rewrites catalog/overrides block-scoped, verifies every version against npm before writing anything, refuses prerelease input, and regenerates the lockfile. Verified: dry-run, prerelease rejection, nonexistent-version rejection, and a full write.
- **Package test scripts** all point at the shared root vitest config so the node lanes actually apply the browser-test exclusion.

### Templates (Router 2.x migration)

- `<Router root={X}><Route .../></Router>` → `createRouter({ routes: defineRoutes([...]) })` with the root as the render-prop child (the official 0.x→2.x mapping), across all 30 router templates.
- `<A>` removed upstream: all links become plain `<a>` (the router claims anchors automatically); the one `end`-match usage moves to `useLinkState().current()`.
- 29 template `tsconfig.json` files had a stale `jsxImportSource: "solid-js"` that broke `tsc` against the Solid 2 line (no `solid-js/jsx-runtime` export); corrected to `@solidjs/web`, matching the base config.
- Verified: Router 2.x runtime smoke test (memory-history render) in a sandbox, and all 30 templates pass `tsc` + `vite build` against published `@solidiom/*@0.6.0`. Templates remain gated by `pnpm --filter '@solidiom/template-*' build` (31/31 passing).

### Package source changes

The only shipped source change in the published catalog is a type-compatibility fix:

- **`@solidiom/file-input`** — the dropzone `dropzoneProps()` cast needed an extra `unknown` step against Solid rc.20's stricter `JSX.HTMLAttributes` index signature. No behavior change.

### Testing and CI

- **Docs e2e made runnable again**: Astro 7's `astro dev` daemonizes (the spawned process always exits early from Playwright's view) and its per-project lock file made the command exit when any dev server held the lock. The `webServer` command now spawns `astro dev --ignore-lock --port <E2E_PORT>` with a port-configurable base URL, and `reuseExistingServer` is unconditional.
- **Site e2e load flakes fixed at the root cause** (reproduced failing under full parallel load, green in isolation): drawer Escape press retried via `toPass` at the same cadence as the open assertion, and the site-search accessible-link-text assertion corrected.
- **WebKit coverage restored**: the browser launcher already probes launchability and skips unlaunchable browsers, so webkit + mobile-safari projects run again where the host provides the required ICU.
- **Dead shadcn-parity wiring removed** (`test:parity`/`parity:generate` entry points and the workspace exclusion referenced files that exist only on the `shadcn` branch lineage; the harness stays recoverable from git history).

### Website

- All Astro sources reformatted under prettier-plugin-astro 1.1.0 (37 files; formatting only, no markup or behavior change).

## Upgrade guidance

- **Library consumers**: this is a routine in-lockstep bump. If your app pins `solid-js` below `2.0.0-rc.18`, raise it — the peer floor moved with the window. No published package API changed.
- **Router template users**: if you started from a `vite-solid-router` template before 0.7.0 and want Router 2.x, apply the mechanical mapping above (`createRouter`/`defineRoutes`, `<A>` → `<a>`, `end` → `useLinkState`), or re-create from the updated template.
